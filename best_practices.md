# Repository Best Practices

> **Сервис** = корневая папка `service_1/`, `service_2/`, `service_3/`, `service_4/`, `service_5/`.  
> (Если добавите новые — обновите это определение и workflow.)

## 1) Scope of PR — один сервис/директория

- Один PR должен менять код только в **одном** сервисе/директории.
- Если затронуто **больше одного** сервиса — попроси автора **разделить PR**.
- Если затронуто **больше двух** сервисов — **обязательно** порекомендуй вынести часть изменений в **отдельные PR**, чтобы:
  - упростить ревью,
  - локализовать регрессии,
  - ускорить мерж.

> Игнорируем файлы инфраструктуры на верхнем уровне (`.github/**`, `.cursor/**`, `*.md`, lock-files), они не считаются «сервисом».

## 2) Vue store anti-pattern: никаких `watch()` внутри store

- **Запрещено:** объявлять `watch()` в Pinia/Store.
- **Почему:** Side-effects и наблюдение за реактивностями должны жить ближе к UI-жизненному циклу, либо в переиспользуемом composable.
- **Что делать:** вынести в компонент или composable.

**Было (❌ в store):**

```ts
// stores/user.ts
export const useUser = defineStore("user", () => {
  const name = ref("");
  watch(name, (v) => saveToLocalStorage(v)); // ❌
  return { name };
});
```
